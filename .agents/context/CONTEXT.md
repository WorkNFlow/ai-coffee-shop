# CONTEXT — проект «Бухта Coffee Roasters»

Главная инструкция для ИИ-агента на весь проект. Дизайн (цвета, шрифты, стиль) описывается в отдельном документе — здесь только функционал.

---

## 1. Подробное описание проекта

### О бренде

**Название:** Бухта Coffee Roasters (в обиходе — «Бухта»)  
**Основана:** 2019, Калининград  
**Основатели:** Анна и Дмитрий Соколовы  
**Команда:** 12 человек  
**Позиционирование:** золотая середина между сетевым кофе и узкоспециализированной кофейней для гиков. Своя обжарка, прямые закупки у фермеров, тёплый тон без снобизма.

### Для кого сайт

- Молодые профессионалы 25–40 лет (фрилансеры, удалёнщики) — ищут спокойное место для работы
- Ценители кофе — интересуются сортами и методами заварки
- Туристы в Калининграде и Зеленоградске — ищут атмосферные локальные места

### Тип сайта

Одностраничный сайт-визитка (лендинг). Весь контент **статический** — обновляется вручную через код. **Нет:** базы данных, интернет-магазина, оплат, личных кабинетов, форм с сохранением заявок, админ-панели.

### Языки

Два языка: **русский** (основной) и **английский**. Переключатель RU / EN в шапке сайта. При переключении меняется **весь** текст на странице. Выбранный язык сохраняется в `localStorage` браузера.

### Структура страницы (сверху вниз)

#### 1. Шапка (Header)
- Логотип «Бухта»
- Якорные ссылки на разделы страницы (плавная прокрутка)
- Переключатель языка RU / EN

#### 2. Первый экран (Hero)
- Короткий слоган и атмосфера бренда
- Кнопка «Узнать больше» — прокрутка к разделу «История»

#### 3. История бренда (About)
- История семьи Соколовых, философия названия «Бухта»
- Ценности: прямые закупки, минимум отходов, просветительская работа

#### 4. Меню (Menu)
- Напитки на основе эспрессо и альтернативные методы (V60, Aeropress, Chemex)
- Еда: выпечка, завтраки, сэндвичи
- Цены — статический текст
- Кнопка **«Заказать зерно»** → открывает модальное окно с формой (EmailJS, тема письма: «Заказ зерна» / EN: «Order coffee beans»)

#### 5. О зерне и обжарке (Roasting)
- Подход к закупке и обжарке
- Сезонные и ограниченные партии
- Подписка «зерно месяца» — описание без онлайн-оплаты
- Кнопка **«Заказать зерно»** → открывает модальное окно с формой (EmailJS, тема: «Заказ зерна»)
- Кнопка **«Подарочная карта»** → открывает модальное окно с формой (EmailJS, тема: «Подарочная карта» / EN: «Gift card»)

#### 6. Локации (Locations)
- Встроенная интерактивная карта **Яндекс.Карт** с метками
- Карточки локаций:
  - 3 действующие точки в Калининграде (адрес, часы работы, фото)
  - Зеленоградск — «Скоро откроемся, осень 2026» (без полного адреса или с примерным районом)
- Ссылка «Построить маршрут» на каждой карточке → Яндекс.Карты

#### 7. Каппинги и курсы (Events)
- Описание регулярных каппингов (дегустаций) и курсов по заварке
- Кнопка **«Записаться на каппинг»** → открывает модальное окно с формой (EmailJS, тема: «Запись на каппинг» / EN: «Cupping registration»)

#### 8. Вакансии (Careers)
- Текстовое описание открытых позиций (статический контент)
- Кнопка **«Откликнуться»** → открывает модальное окно с формой (EmailJS, тема: «Отклик на вакансию» / EN: «Job application»)

#### 9. Контакты (Contact)
- Email, телефон, часы работы
- Ссылки на Instagram и Telegram (внешние ссылки, открываются в новой вкладке)

#### 10. Подвал (Footer)
- Копирайт © 2019–2026 Бухта Coffee Roasters
- Повтор ключевых контактов и часов работы

### Сценарии использования

**Сценарий 1 — Турист после Instagram:**  
Открывает сайт на телефоне → листает первый экран и историю → смотрит меню → проверяет ближайшую локацию на карте → нажимает «Построить маршрут».

**Сценарий 2 — Покупка зерна:**  
Гость читает раздел «О зерне» → нажимает «Заказать зерно» → открывается модальное окно с формой → заполняет имя, email, сообщение → отправляет через EmailJS → письмо приходит на hello@bukhta.coffee.

**Сценарий 3 — Запись на каппинг:**  
Гость находит раздел «Каппинги» → нажимает «Записаться» → открывается модальное окно с формой → заполняет и отправляет через EmailJS.

**Сценарий 4 — Англоязычный турист:**  
Нажимает EN в шапке → весь текст переключается на английский → смотрит меню и адреса.

**Сценарий 5 — Отклик на вакансию:**  
Гость листает до «Вакансии» → читает описание → нажимает «Откликнуться» → открывается модальное окно с формой → заполняет и отправляет через EmailJS.

### EmailJS — сервис отправки форм

**Сервис:** [EmailJS](https://www.emailjs.com/) — отправка email прямо из браузера, без backend.  
**Тарифный план:** Free (200 писем/месяц, 2 шаблона).  
**Библиотека:** `@emailjs/browser` — устанавливается через npm.

**Необходимые переменные (получить в личном кабинете EmailJS):**
- `EMAILJS_SERVICE_ID` — ID подключённого email-сервиса
- `EMAILJS_TEMPLATE_ID` — ID шаблона письма
- `EMAILJS_PUBLIC_KEY` — публичный ключ аккаунта

**Хранение ключей:** в файле `.env` в корне проекта (добавить в `.gitignore`). В Astro доступны как `import.meta.env.PUBLIC_*`.

**Компоненты:**
- `ContactModal.tsx` — переиспользуемый модальный компонент с формой (React, клиентская сторона)
- Все кнопки, ранее открывавшие mailto, теперь открывают этот модал с нужной темой письма

**Шаблон письма (EmailJS dashboard):** должен содержать переменные `{{from_name}}`, `{{from_email}}`, `{{subject}}`, `{{message}}`.

### Принципы организации

- **Один файл = одна секция страницы** — каждый блок лендинга в отдельном компоненте
- **Данные отделены от разметки** — меню, локации, контакты лежат в `src/data/`, тексты UI — в `src/i18n/`
- **Переводы в JSON** — все строки интерфейса в `ru.json` / `en.json`, без хардкода текста в компонентах
- **Статическая сборка** — `output: 'static'` в astro.config; результат сборки (`dist/`) загружается на Timeweb как обычные файлы

## 3. Правила для ИИ-агента

1. **Проверка скиллов.** Перед выполнением абсолютно любой задачи — включая планирование, написание кода, исправление ошибок и любые другие — сначала проверить папку `.agents/skills` в корне проекта на наличие подходящего скилла для этой задачи. Если подходящий скилл есть — использовать его. Если подходящего скилла нет — выполнять задачу без него, но проверку пропускать нельзя никогда.

2. **Никаких заглушек.** Не оставлять незавершённый код (`// TODO`, `// остальной код здесь` и т.п.). Либо функция реализована полностью, либо не включена вообще. Если агент не может завершить задачу — объяснить почему и спросить, а не оставлять недоделанное.

3. **Конфигурационные файлы.** Никогда не удалять и не изменять конфигурационные файлы (`.env`, `package.json`, `astro.config.mjs`, `tsconfig.json` и подобные) без явного подтверждения пользователя.

4. **Секреты.** Никогда не коммитить секреты, ключи API и пароли.

5. **Версии библиотек.** Перед использованием библиотеки или API — убедиться, что она действительно установлена в проекте и существует именно в версии из `TECH.md`, сверяясь через Context7 MCP, а не полагаясь на память.

6. **Контрольные точки в git.** Перед началом любого изменения, затрагивающего несколько файлов, — сделать промежуточный commit в git («контрольная точка»), и коммитить снова после каждого успешно проверенного изменения.

7. **Только запрошенный функционал.** Не добавлять функциональность, которую не просили — делать ровно то, что описано в задаче, без «улучшений от себя».

8. **Неоднозначные решения.** Если решение может пойти в разных направлениях — сначала спросить пользователя, а не выбирать самому.

9. **Единый стиль.** Придерживаться единого стиля именования файлов (PascalCase для компонентов `.astro`, camelCase для утилит и переменных, kebab-case для CSS-классов), папок и функций на протяжении всего проекта.

10. **Без дизайна в коде.** Не принимать решения о цветах, шрифтах, отступах и визуальном стиле — это описывается в отдельном дизайн-документе. Использовать нейтральную вёрстку или плейсholder-стили до получения дизайн-спецификации.

11. **Два языка всегда.** Любой новый текст, добавляемый на сайт, должен быть добавлен и в `ru.json`, и в `en.json`.

12. **Без backend.** Не добавлять серверную логику, API routes, базы данных. Связь с кофейней — через EmailJS (клиентская библиотека). Ключи EmailJS хранить в `.env`, не коммитить в репозиторий.
